# Windows 团队本地部署

## 初次使用（主机操作一次）

1. 将 StockPilot 文件夹解压到固定位置，例如 D:\StockPilot。不要直接在压缩包中运行。
2. 主机安装 Node.js 24 LTS。其他同事只需要浏览器，无需安装 Node.js 或此项目。
3. 如之前运行过 npm run dev，请关闭那个黑色窗口，避免占用同一个5173端口。
4. 双击 Start.vbs。后台启动服务并打开浏览器；弹窗显示随机生成的团队访问口令。无需打开 CMD、npm 安装或构建。
5. 使用弹窗中的口令登录。以后可在 .stockpilot/access-code.txt 找到，或者双击 LAN-address.vbs 查看。
6. 若希望登录Windows后自动运行，双击 Enable-startup.vbs（仅当前用户）；不自动打开网页。取消则双击 Disable-startup.vbs。这是登录后启动，尚不是无需登录的系统服务。服务器需保持开机、不休眠、用户不注销；锁屏可继续运行。

若 Windows 提示文件来源未知，先核对下载来源。若公司策略禁用 VBS/PowerShell，请联系 IT 按公司规范安装，不要修改组织安全策略。本部署的启动脚本尚需在实际 Windows 电脑验证；云端已验证 Node 服务与浏览器团队流程。

## 给同事使用

1. 双击 Enable-LAN.vbs，允许管理员授权；它仅添加“专用网络 + 本地子网 + Node程序 + TCP5173”的入站规则，不关闭防火墙、不开放公网。域网络由IT配置。
2. 双击 LAN-address.vbs，显示这台主机的局域网地址和访问口令。地址列表也保存到 LAN-addresses.txt，里面不保存口令。
3. 将合适地址（常见为192.168开头，例如 http://192.168.1.150:5173/）和口令通过公司内部渠道发给同事。同事须处于可互通的同一局域网，浏览器打开并登录。建议路由器给主机固定IP。
4. 所有人共用美国、德国两份工作区，页面每5秒更新。正在编辑输入框时暂缓刷新；可随时点击“载入最新数据”。同一版本的并发修改只接受第一份，后保存者提示重新载入，不覆盖别人的更改。

此版采用团队共享口令，尚无个人账号、角色或操作者审计。只用于可信内网，使用HTTP，不要将5173端口映射到公网。所有持有口令的人均能修改和清空团队数据。登录8小时过期，服务重启后需重新登录。

## 原有数据迁移

原来的本地试用数据在各自浏览器中，不会被自动上传。停止旧服务之前，先在旧页面导出 JSON 工作区。新团队服务登录后，选择对应市场导入该JSON；导入会替换该市场的团队数据，影响所有人。

## 备份、更新、停止

- 业务数据与口令保存在主机的 .stockpilot 文件夹，绝不推送到GitHub。US.json、DE.json分别存两国工作区；写入前会自动备份上一个已保存版本到 backups/。备份会持续增长，定期由管理员归档；它们不替代异机备份。
- 建议每天导出 JSON，并定期停止服务后将整个 .stockpilot 文件夹复制到其他磁盘。恢复时先停服务，用备份覆盖对应US.json/DE.json，再启动。不要在服务运行时手动编辑数据文件。
- 更新：先备份并双击 Stop.vbs，再将新版部署包的文件覆盖到同一个目录，保留 .stockpilot 文件夹，然后 Start.vbs。部署包不含该文件夹；不要通过删除整个旧目录的方式更新。若搬迁目录，重新设置开机启动。
- 双击 Stop.vbs 停止此安装启动的服务。它会核对进程，避免结束其他Node程序。关闭网页不会停止后台；关机将停止所有同事访问。
- 修改口令：停服务，在 .stockpilot/access-code.txt 写入至少12位新随机口令，再启动，通知同事。不要在聊天或公开仓库中提供实际口令。
- 排查：查看 .stockpilot/error.log；不要分享 access-code.txt 或完整业务数据。网络无法访问时检查主机休眠、专用网络、公司防火墙和Wi-Fi客户端隔离。

## 直接上传 TikTok 和领星原始导出

美国/德国工作区的三个导入入口可直接读取 TikTok 订单 CSV、领星仓库库存 XLSX、领星海外仓备货单 XLSX，不必改列名或删除其他工作表。选择文件后查看自动识别预览，再点击“导入当前市场”。库存快照日期必须确认；在途“预计到货时间”的含义不确定时保留默认“不抵扣供给”，不要当成已上架日期。

只有补货字段及识别摘要会保存在主机上，买家姓名/电话/地址/支付信息不进入团队工作区。原文件留在你自己的电脑，部署包不含任何真实业务文件。

## 在软件中在线更新（0.2.0及之后）

旧版没有更新入口，第一次需要手动安装带在线更新功能的部署包：先 Stop.vbs，备份 .stockpilot，覆盖程序文件但保留 .stockpilot，再 Start.vbs。之后不用反复下载解压。

在主机浏览器通过 http://localhost:5173 登录，点击“检查更新”。有新版本时显示版本与说明，点击“备份并更新”并确认。程序从本项目 GitHub 官方仓库下载包，校验 SHA256 和每个文件后才暂停写入，备份当前数据和程序，然后重启并验证登录及美德数据可读性。更新期间所有同事暂时无法修改，完成后页面刷新并要求重新登录；口令不变。局域网同事不能触发更新。主机打开192.168地址时也需改用localhost操作。

更新只写程序目录，不覆盖 .stockpilot 业务目录。数据备份与旧程序位于 .stockpilot/updates/每次更新编号/ 下的 data-backup、software-backup。若新版本未通过启动和数据校验，会尝试自动回退。不要在更新途中关机、睡眠或移动文件夹；更新期间请通知同事暂停操作。

若检查/下载失败，现有版本继续运行；请检查主机能否连接 raw.githubusercontent.com。无需提供GitHub口令，不上传本地业务文件。若下载期间官方新版再次变化导致校验失败，重新检查后再更新，不绕过校验。

若显示“自动恢复未完成”，先保留整个 .stockpilot/updates 和 update-worker.log，请IT核查服务已停止后从对应software-backup与data-backup恢复。确认没有更新进程运行后才移除 .stockpilot/update-lock 并重新启动。不要直接删除 .stockpilot 或在服务运行时覆盖业务JSON。

更新流程已在云端用真实独立Node进程验证正常升级和失败回退；Windows后台进程及防火墙仍需在实际主机确认。此功能使用可信内网HTTP和团队口令，尚无个人角色权限，不用于公网。

## 补货提醒 Agent

安装0.3.1后，Start.vbs启动的服务会自动运行补货提醒Agent。软件右上角“补货提醒”可看今天需处理、即将到期、预计缺货与资料待核实。当前只监控美国，按北京时间09:00左右汇总、每15分钟巡检，导入数据后重评；在主机localhost的自动巡检设置中可改时间和提前天数。德国巡检暂不开放，旧配置会按美国范围运行，德国业务数据不会删除。

若已安装0.2.0，可直接“检查更新 → 备份并更新”；无需重新手动解压。后台主机必须开机、不休眠且服务运行。没有最新数据时，Agent会提醒更新数据，不自动编造库存或采购数量。已读状态团队共享，并不表示采购完成；需要把真实发货更新为在途后重新评估。

如需桌面弹窗，在自己的浏览器点击“开启本浏览器通知”并允许。页面需保持打开及登录；主机localhost支持，普通192.168局域网HTTP通常不支持通知，但提醒中心始终可用。同事需要HTTPS才能开启这类浏览器通知；本部署未自动配置HTTPS。设置和已读状态在 .stockpilot 中，升级时保留。

## 先看SPU，再展开SKU

“备货建议”和“补货提醒”均以SPU/产品卡片先展示，点击卡片展开对应SKU建议。每个SPU单独展开，修改策略后保持展开状态；重新打开页面默认收起。缺少SPU的记录明确标为待识别，不会按相近SKU猜测合并。全部SKU仍会出现在导出清单中。

## SKU识别不出SPU时手动归类

升级0.3.2后，点击备货建议右侧“手动归类SKU”，勾选一个或多个待识别SKU，在“目标SPU”选择已有款号或输入新款号，点击“保存归类”并确认。保存后会归入该SPU卡片，展开可看到各尺码颜色的独立建议。

归类规则由同事共用，刷新、重启和普通表格重新导入后仍保留。可切换“已手动归类”修改，或选择“恢复所选SKU自动识别”撤销。手动归类只改变产品分组，不会把不同SKU库存互相抵扣；归入新SPU后使用目标SPU策略和经营参数，请核实选对款号。
